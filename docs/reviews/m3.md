## Findings and dispositions

### Blocker — the M3 facade duplicated the task kernel

The initial compiler facade owned a second task-state enum, current array,
ready queues, placement rule, context transfer, and dispatcher loop. That made
M2's checked boundary a disconnected design model.

Disposition: fixed. `Flyology.Task_Core` is now the one production authority
for task scheduler state, current ownership, waits, queues, contexts, and idle.
All state transitions call `Dispatcher_Model.Try_Transition`; ready publication
and selection call `Scheduler_Contract`; the GNARL facade retains only compiler
body, activation-group, master, and abort-deferral metadata. Policy code never
switches context.

### Blocker — idle could lose a remote wake

Both dispatchers originally released the RTS lock after observing an empty
queue and then slept without a request-epoch handshake. x86 also returned from
idle with interrupts disabled.

Disposition: fixed. While still holding the queue lock, the core snapshots the
per-core requested epoch. x86 masks, rechecks, and uses the architectural
`sti; hlt` sequence, returning with IF enabled. AArch64 masks, acquire-rechecks,
uses masked-pending-IRQ `wfi`, and unmasks on return. Remote publication
precedes epoch increment and IPI/SGI. Six repeated SMP4 runs exercise this path.

### Blocker — ordinary waits did not bind the exact-wake contract

Activation and master waits initially transitioned a task directly without the
generation-bearing token required for later GNARL synchronization.

Disposition: fixed. The authoritative per-task record retains wait phase and a
nonwrapping generation. Arm, commit/block, and exact wake validate the complete
`Task_Ref` and generation under the global RTS lock. Activation stores the exact
token until the final activation acknowledgement; master completion stores it
until the final dependent terminates.

### Blocker — environment task identity appeared after elaboration

The first implementation registered the environment only after `adainit`, so a
tasking hook during application elaboration had no current task.

Disposition: fixed. The architecture validates topology and publishes the boot
CPU count before `adainit`; `Flyology.M3_Runtime` adopts it during its package
body elaboration and registers slot 0. Binder evidence orders `System.Tasking`,
`Task_Core`, and `M3_Runtime` before `Soft_Links` and application elaboration.
AP release remains after complete `adainit`.

### Blocker — x86 called Ada before enabling FP/SIMD

Compiler-generated validation could execute while Limine base revision 6 still
had FP/SIMD disabled.

Disposition: fixed. x86 validates and enables the deliberately bounded
x87/SSE/XSAVE state before the first Ada or injected last-chance call. AArch64
continues to enable base FP/SIMD and normalize EL1 before Ada on BSP and APs.

### High — identity observations raced termination

`Is_Callable` and `Is_Terminated` initially read mutable state without the RTS
lock while another core could retire the task.

Disposition: fixed. Current-task and identity-state queries take the global
lock and read the one core task record. Retained identities remain queryable
after normal termination.

### High — proof and evidence claims exceeded reproducible coverage

Activation contracts omitted frame conditions, a hosted master experiment was
described as authoritative, layout checking was absent, and each QEMU cell ran
only once.

Disposition: fixed. The activation reference model now proves stable identity,
master/dependent updates, batch-ready publication, rejection equality, and
termination frames. The tracked record labels hosted experiments
non-authoritative and moves abnormal/unactivated cleanup to M4. The closing
gate includes ABI layout checks, a stable host-model hash, and repeated SMP4
stress. GNATprove was raised to level 2 and its shared output is locked.

## Perspective review

- Architecture and boundary integrity: GNARL-compatible staging owns language
  lifecycle; Task_Core owns scheduler state and context handoff; the FIFO policy
  owns ordering only; architecture code owns privileged state and notifications.
- Systems/hardware correctness: both fixed QEMU machines boot SMP1/4, APs enter
  owned stacks after elaboration, and idle wakes by x2APIC IPI or GICv3 SGI.
- Ada/GNARL compatibility: application tasks arise only from ordinary Ada task
  declarations and compiler-generated `Create_Task`/`Activate_Tasks` calls.
  Stable standard `Task_Id`, `Current_Task`, callable/terminated queries, normal
  activation, lexical masters, and nested task masters are exercised.
- SMP and atomics: specific tasks simultaneously enter one barrier per core;
  automatic tasks cover every eligible core on SMP4. Queue/current/master
  changes are serialized while task bodies execute concurrently outside the
  global lock. Publication precedes remote notification.
- Interrupt/ABI/context: x86 is built without a red zone; voluntary contexts
  preserve the target ABI and enabled FP control state. Interrupt frames and
  exception stacks remain the separate M2 mechanism; M3 makes no preemption
  claim.
- Scheduler-policy separation: the bounded FIFO policy selects and returns a
  reference but cannot mutate task state/current ownership or switch context.
  Alternative policies remain M5 and domains remain M6.
- Memory and lifecycle: the image has 15 non-environment static task slots and
  retained aligned 64 KiB stacks with bottom canaries. No slot reuse,
  reclamation, dynamic task allocation, or general allocator is claimed.
- SPARK soundness: 156 checks cover deterministic validation, transition,
  placement, queue, reschedule, and bounded activation reference kernels.
  No hardware mirror ghost state, assumptions, or disabled implementation body
  is used. Concurrent integration remains test/review evidence, not proof.
- Security/fail-closed behavior: unsupported CPU count/aspect, invalid identity,
  illegal transition, queue exhaustion/duplication, wait mismatch, stack-canary
  corruption, and abnormal unwind terminate through structured failure paths.
- Verification and observability: the gate requires unique online and semantic
  pass markers plus absence of failures. Barriers and master waits causally
  precede the summary markers. Stress is repeated deterministic coverage, not
  exhaustive interleaving exploration.
- Portability and claims: evidence covers only QEMU 10.2.0 TCG,
  `pc-q35-10.2`, `virt-10.2`/GICv3, SMP1/4, and the pinned firmware/boot inputs.
  No physical hardware, hosted CI, ACPI/DT discovery, AVX, or SVE claim exists.
- Licensing: the runtime is original MIT/Apache-2.0 clean-room work. The
  compiler-facing surface comes from owned sources, generated expansion/ALI/nm,
  public contracts, and black-box behavior; no GNAT runtime source is tracked
  or used as implementation input.

## Subtraction review

The duplicated M3 ready queue, current array, task-state enum, dispatcher loop,
and task-stack/context authority were removed rather than adapted. There is no
public Spawn, fiber, scheduler, or task-creation API. The compiler facade is a
narrow semantic adapter, and only one concrete FIFO policy remains because M3
needs deterministic ready ordering. The global RTS lock remains intentionally
unsharded.

## Residual risks and unsupported claims

- M3 covers normal activation, normal body return, normal completion, and
  normal master observation only. `Expunge_Unactivated_Tasks`, activation
  failure, exception propagation, abort, abnormal master cleanup, protected
  objects, rendezvous, delays, priority/ceiling behavior, and reclamation remain
  unsupported and fail closed. They are M4 gates.
- Task storage is bounded to 15 non-environment tasks with retained 64 KiB
  stacks. No identity generation increment or reuse occurs yet.
- The bounded activation model is a reference model; production uses the proved
  transition/scheduler/placement kernels directly, but the concurrent admission
  transaction and GNARL facade are not SPARK-proved.
- No interrupt-time task context switch occurs. Timer/IPI-driven real
  preemption and no-yield progress remain M5.
- Same-host independent-output-root determinism is not independently
  provisioned clean-room reproducibility.
- Shellcheck was unavailable. Shell syntax/static checks, warnings-as-errors,
  proofs, models, layouts, ELF inspections, reproducibility, and QEMU gates ran.

## Decision

M3 is complete at `faabe4e0795e5a3472f7f531c97994a0b55e43a9` for the narrowly
defined ordinary-Ada normal lifecycle: activation, standard identity, separate
stacks, specific and automatic placement, normal termination, and lexical and
nested masters on both architectures at SMP1/4. This decision does not claim
M4 cross-core synchronization/abnormal semantics or M5 preemption.
